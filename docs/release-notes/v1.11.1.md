# WiiKart 1.11.1

The boot failure from issue #1, properly diagnosed this time.

## What was actually wrong

`elf2dol` writes each section's exact ELF byte count into the DOL header,
and ends the file at the last section's exact size. A loader handles
sections in **32-byte units**, so it wants up to 31 bytes per section that
the header never described and the file does not contain. Dolphin's
`DolReader::Initialize` then refuses the whole executable, and all you see
is **"Failed to init core"** — reported before the console executes one
instruction, which is why nothing the game logs can tell you about it.

v1.11.0 fixed the file-length half. This release fixes the other half:
every nonzero section size is now rounded up to 32 as well.

## Why this is the answer

Held to builds actually tested on the reporter's machine, one property
separates them cleanly:

| Build | `text0` size mod 32 | `data0` size mod 32 | Result |
|---|---:|---:|---|
| v1.4.0 | 0 | 0 | **boots** |
| v1.5.0 | 12 | 0 | fails |
| v1.6.0 | 4 | 0 | fails |
| v1.10.0 | 8 | 0 | fails |
| v1.5.1 | 12 | 0 | fails |
| v1.5.2 | 28 | 28 | fails |

v1.4.0 is the last build in which every section size happened to be a
multiple of 32 already. Nothing else about the startup path changed at
v1.5.0 — `main()` is byte-identical between the two.

The decisive test was v1.5.2: a bare video-and-console program, built from
the same tree, Makefile, libraries and pinned toolchain, with none of the
game in it. It failed too. That ruled out everything WiiKart does and left
only the shape of the binary.

The fix is safe in both directions. A rounded-up section covers padding
`elf2dol` already wrote, and reaches exactly the next section's 32-byte
aligned load address — never past it. For the last section the rounding can
reach a few bytes into the start of BSS, which crt0 zeroes before `main`.
Run against the published binaries it is a **no-op on v1.3.0 and v1.4.0**,
the two builds known to boot, and normalizes every other release to the
same shape as v1.4.0.

## A correction

v1.11.0's notes claimed the alignment theory in issue #1 was disproved. That
was wrong. The counterexamples used were v1.0 through v1.2.1 — unaligned
sections, reported working — but those were the wrong control: they were
last run on an older Dolphin, and they are separately 12 to 28 bytes short,
which disqualifies them on a current one. They said nothing about the
install actually reporting the fault.

## Playing it

Download `wiikart.zip`, unzip, and open `wiikart.dol` in
[Dolphin](https://dolphin-emu.org) (File > Open). On a real Wii, copy the
`apps` folder to an SD card and launch it from the Homebrew Channel.

If you want the controlled comparison rather than the newest build,
`wiikart-1.5.3.zip` on the v1.5.0 release page is v1.5.0 with this one
change and nothing else.
